# Python 示例逐项学术与实现一致性审查

范围：`source code/` 的全部 15 个 Python 文件、README 命令及双语 D7。重点是代码是否实现所声称的代数、尺度、模数变换和功能。本次没有把教学代码升级为可部署的密码库；也没有实现完整 TFHE/BFV/BGV/CKKS 自举。

所有可运行的确定性检查见 `check_python.py`。维护中的四个示例覆盖 31 种方案/操作组合，每种检查固定输入和固定种子的随机输入，共 62 个运行子例。旧独立脚本的辅助算术分别加载检查，启动时的全部随机配置并未穷举。


## CODE-001　模拟 PBS / 电路自举包含明文秘密密钥

**级别：高；状态：限制已明示；模拟保留。** 文件：`tfhe_lib.py`、`tfhe_example.py`、`d07-python-demo-library.tex`。

**原问题。** 函数名称和 README 可能使读者将功能模拟当作可公开求值的 TFHE 自举实现。

**核验。** tfhe_bootstrap_keygen 返回含 s 的 mock_bk 字典；tfhe_mock_pbs 实际计算 b+a·s，解密消息后查询表并重新加密。此行为在原代码注释中已有提示，不能据此指控作者隐瞒，但教材功能边界仍需明确。

**处理。** 双语 D7、README 和函数文档明确标为客户端功能模拟；移除含混的“可能是真实 PBS”说明。密文乘法默认路径另行说明为张量乘积变体；动态匹配 GSW 分解层数。

## CODE-002　三个自举空实现返回数字 0

## CODE-003　BFV t/q 缩放前错误使用 q·floor(q/t) 截断

**级别：高；状态：已修正。** 文件：`bfv_lib.py`、`common.py`。

**原问题。** 代码注释说“不先模约减”，实际在 qΔ 下算乘积，再按 t/q 缩放。qΔ 经 t/q 缩放得到 tΔ=q−r，不是 q 的整数倍。

**核验。** N=2,t=17,q=8191,Δ=481,s=[1,−1]；m1=[2,3],m2=[1,−8]。无加密和评估钥噪声时，a1=[2715,3314],b1=[3124,844],a2=[4710,5559],b2=[−1597,3494]。旧算法解得 [8,4]，正确负循环乘积 mod17 为 [−8,4]。

**处理。** 增加 exact integer negacyclic product；先在整数环中形成乘积和交叉项，再 t/q 缩放舍入与重线性化。BFV 解密统一为标准 t/q。check_python.py 同时重现旧结果与修正结果。

## CODE-004　CKKS 示例解密时没有更新实际尺度

**级别：高；状态：已修正。** 文件：`ckks_lib.py`、`ckks_example.py`。

**原问题。** 乘法后删除 q_last，但仍用旧 encoder.scale 解密，近似相等的模数掩盖了比例误差。

**核验。** Δ=100,q_last=97 时实际尺度为 10000/97；固定相位示例用旧尺度解得 1.03，而按实际尺度约为 0.9991。

**处理。** 增加 ckks_rescaled_scale，示例分别跟踪输入与输出尺度；禁止在只剩一个因子时继续重缩放；函数文档明确 Q_BASE 会被修改。

## CODE-005　旧实验脚本采用了错误的多项式约减符号

**级别：高；状态：已修正。** 文件：`bgv.py`、`rns.py`、`bfv.py`、`bfv_rotation_only.py`、`ckks.py`。

**原问题。** bgv.py/rns.py 按 X^N−1 循环卷积；另三文件的 −1 ** (degree/n) 受优先级影响总先算幂再取负，且使用浮点除法。

**核验。** 在教材的环中 X^N=−1、X^(2N)=1；旧前两者将第一式算成 +1，旧后者对第二式也用负号。

**处理。** 统一负循环符号 (−1)^(degree//N)，避免修改输入数组；加入 X^N 和 X^(2N) 的固定反例及 NTT 对照。

## CODE-006　RNS 精确基转换不能正常调用，模切换依赖外部全局基

**级别：高；状态：已修正。** 文件：`rns.py`。

**原问题。** FastBConvEx 使用不存在的 operator.mult，将整数当基列表，并对列表做减法；ModSwitchRNS 还读取与函数参数无关的全局 b_base。

**核验。** 这些错误使未被顶层随机样例调用的精确转换路径无法验证。附加模数不足时也不能唯一恢复 carry。

**处理。** 按冗余模数恢复 carry；明确 |x|≤B/2 和辅助模数界。ModDrop 选择原有剩余；ModRaise 使用精确中心 CRT；ModSwitch 用实际删除基的乘积及精确中心余数。小完整剩余空间和多组基测试通过。

## CODE-007　负数的二进制分解不精确且截断静默发生

**级别：高；状态：已修正。** 文件：`common.py`、`tfhe_lib.py`。

**原问题。** 平衡分解在 base=2、x=−1 时不断产生 +1；给定 L 不足时仍返回看似完整结果；base=1 可导致无穷循环。

**核验。** q=17,base=2,L=6 时旧输出六个 1，重构为 63≡12 mod17，而非 −1≡16。

**处理。** 偶数基的半基数 tie 根据剩余符号选取；限制参数并在精确分解长度不足时抛错。TFHE 无符号分解先把输入转到 [0,Q)，并明确精确容量条件。

## CODE-008　四种解密 API 的可选参数实际不可省略

**级别：中；状态：已修正。** 文件：`tfhe_lib.py`、`bfv_lib.py`、`bgv_lib.py`、`ckks_lib.py`。

**原问题。** expected_dec 默认 None，但返回的 e_bits 或 max_abs 只在提供参考明文后定义。

**核验。** 四个默认调用均复现 UnboundLocalError。参考明文缺失时不能凭空计算“真实误差”。

**处理。** 统一返回 (message, None) 表示无参考诊断；保留提供参考时的诊断；删除 BGV 解密的无条件打印。

## CODE-009　命令行参数与错误退出状态掩盖失败

**级别：中；状态：已修正。** 文件：`tfhe_example.py`、`bfv_example.py`、`bgv_example.py`、`ckks_example.py`、`README.md`。

**原问题。** 读取没有注册的 args.bootstrapping；README 使用 --encryption/--encoding 等不存在的参数及 TFHE --rotate；失败分支 sys.exit(0)。CKKS --conjugate 未正确启用加密，--all 也遗漏它。

**核验。** 错误退出码 0 会使外部脚本把失败当成功。对指定参数及主动构造失败分支分别进行测试。

**处理。** 修正受支持参数和依赖关系，删除不可达自举选项，所有实际错误用退出码 1；README 命令与 parser 对齐。

## CODE-010　示例测试域没有覆盖模明文回绕，精度说明误称百分比

**级别：中；状态：已修正。** 文件：`tfhe_example.py`、`ckks_example.py`。

**原问题。** TFHE 随机消息限制在 sqrt(P−1) 以内，且把合法模 P 回绕当错误；CKKS 用绝对差比较却宣称百分比误差。

**核验。** P=256 下 255+255≡254、255·255≡1；这两例不属于原随机覆盖范围。0.01 的绝对分量误差也不等于 1% 相对误差。

**处理。** TFHE 预期结果按模 P 计算并扩展全消息域；增加回绕反例；CKKS 明确绝对实部/虚部误差阈值。

## CODE-011　大整数模数转换经过浮点数丢失决定舍入的位

**级别：高；状态：已修正。** 文件：`bgv.py`、`rns.py`。

**原问题。** 独立实验用 float 计算模数比值、math.floor(q/p) 或把大整数相位除以 scale 后舍入。

**核验。** 固定大整数例子，精确舍入为 192153584101141163，原 float 路径为 192153584101141152，相差 11。

**处理。** 采用整数乘法及 round_div；RNS BFV 解密用整数 t/q；scale 用整数除法。修正对象数组求模逆需要 refs_ok 的问题。

## CODE-012　旧 CKKS 编码器混用实例与全局参数

**级别：中；状态：已修正。** 文件：`ckks.py`。

**原问题。** 构造函数接受 N、scale，但矩阵维数、单位根阶和解码仍使用全局 N、M、scale。

**核验。** 全局 N=8,M=16,scale=10000，与实例 N=4,scale=100 不一致时，旧实现不遵守接口参数。

**处理。** 矩阵、典范映射和解码统一使用实例参数，增加这一异配置往返测试。

## CODE-013　非正数被视为 2 的幂，密钥切换注释相位相反

**级别：中；状态：已修正。** 文件：`common.py`、`bfv.py`、`bfv_rotation_only.py`、`ckks.py`、`tfhe_lib.py`。

**原问题。** 旧 IsPowerOf2 对 0 和负数返回 True，并经浮点除法处理大整数；TFHE 的 keyswitch 注释使用减号，而实现使用加号。common 的评估钥注释也与实际存储符号相反。

**核验。** 直接检查 0、−1、2^70；按加号相位展开实际累加式，代码算法可以正确但注释会指导出相反实现。

**处理。** 使用正整数位运算；NTT 单元素输入直接取单位根 1，避免为常数多项式遍历大模数；校正两套相位约定的文档，不无根据地翻转原来正确的代码符号。

## CODE-014　教学参数、采样与完整实现的边界不清

**级别：中；状态：限制已明示。** 文件：`README.md`、`d07-python-demo-library.tex`、`common.py`、`bfv_j_matrix_inverse_proof.py`。

**原问题。** 小参数运行成功和固定矩阵打印不能构成一般正确性证明或安全级别证明；“增大 N 后也增大 Q”的建议没有安全约束。

**核验。** 维护示例默认 N=4，秘密/误差包含 Python 或 NumPy 随机采样；旧编码脚本根本没有加密。提高固定维数下的模数也会影响安全性。

**处理。** 文档区分教学实验、真实密文操作、客户端模拟和空实现；明确需要独立参数/随机性分析。矩阵脚本保留为数值示例，不宣称证明所有尺寸。

## 实现依据及限制

BFV 缩放修订对应 Fan–Vercauteren 原论文 §4 的整数环乘积和 t/q scale-and-round；CKKS 对应原论文 §3.3 的 rescaling 与误差项。具体一手全文链接见 `summary-review.md`。其余代码缺陷可直接由仓库基线和反例复现，报告不把单次测试当作通用定理。

15 个文件均作静态核对，单元测试覆盖确认的问题。没有进行常数时间、旁信道、生产密钥管理、所有可能参数的安全估计或完整密码库互操作验证。旧实验仍使用全局配置和大量打印；这些属于教学代码的保留限制。

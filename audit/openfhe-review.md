# OpenFHE 中的 Meta-BTS 实际同态核验

## 实验目的与固定版本

本实验补充 `CBR-016`、`CBR-017` 的理论审查：检查真实 CKKS 密文经过一轮和两轮自举后，默认 REAL 解码接口观测到的输出与输入差值，并观察预先存在于代表值中的扰动是否保留。它使用公开求值钥执行 `EvalBootstrap`，没有用解密—查表—重新加密替代自举。以下实验精度包含解码观测误差，不直接等于未经投影的复典范相位误差。

固定上游 [OpenFHE v1.6.1](https://github.com/openfheorg/openfhe-development/tree/b59e1f291965f14fbee5172cd83a20f5b856204f)，完整提交为 `b59e1f291965f14fbee5172cd83a20f5b856204f`。配置/API 用法参考该提交的 [iterative-ckks-bootstrapping.cpp](https://github.com/openfheorg/openfhe-development/blob/b59e1f291965f14fbee5172cd83a20f5b856204f/src/pke/examples/iterative-ckks-bootstrapping.cpp)，并直接核对 [EvalBootstrap 实现](https://github.com/openfheorg/openfhe-development/blob/b59e1f291965f14fbee5172cd83a20f5b856204f/src/pke/lib/scheme/ckksrns/ckksrns-fhe.cpp) 中的缩放、求差、第二次自举和回缩放顺序。驱动程序保留 BSD 许可与来源说明。

可复查材料：[测量程序](openfhe_meta_bts.cpp)、[构建配置](openfhe-CMakeLists.txt)、[运行脚本](run_openfhe_meta_bts.py)、[完整结果](openfhe-results.json)。结果包含 API 返回的逐槽数值、输入和两轮输出的实际尺度/模数塔数、两轮输出剩余层级、构建命令和源文件 SHA-256。一轮输出的层级与尺度未单独记录。

## 配置和测量方法

| 项目 | 固定设置 |
|---|---|
| 库版本 | OpenFHE 1.6.1，64 位 native 后端 |
| 环维数 / 槽数 | 4096 / 8；稀疏槽布局 |
| 秘密分布 | `UNIFORM_TERNARY` |
| 尺度管理 | `FLEXIBLEAUTO`，普通模数因子 59 bit，首因子 60 bit |
| 解码模式 | 默认 `REAL`、`EXEC_EVALUATION`；包含解码阶段的加噪和实部输出 |
| 线性变换预算 | `[3,3]` |
| 安全等级设置 | `HEStd_NotSet`；本实验配置不对应经认证的安全等级 |
| 输出层数目标 | 10 |
| 试验安排 | 3 个独立进程，各自重新生成密钥和随机加密；每次检查 3 组固定输入 |
| 校准 | 单独的已知校准密文；单轮最大误差精度向下取整后减 5 bit，限制在 1–25 内 |
| 实际校准参数 | 三次分别为 19、19、20 |

令 $v_{in}$ 为输入密文经默认 REAL 接口得到的解码观测值，$v_1,v_2$ 分别为一轮和两轮自举后的同类观测值。测量

$$
E_1=\max_i|v_{1,i}-v_{in,i}|,\qquad E_2=\max_i|v_{2,i}-v_{in,i}|,
\qquad P_j=-\log_2 E_j.
$$

$P_j$ 是单位尺度下按最大绝对观测差定义的精度位数，不是相对误差，也不是密码学安全位数。程序同时保存平均误差，但本报告的结论使用最大误差。小数来自双精度解码，因此不把超过解码表示能力的位数当作证据。

**解码本身也是测量的一部分。** 已直接核对固定版本的 [默认参数](https://github.com/openfheorg/openfhe-development/blob/b59e1f291965f14fbee5172cd83a20f5b856204f/src/pke/include/scheme/gen-cryptocontext-params-defaults.h)、[Decode 接口说明](https://github.com/openfheorg/openfhe-development/blob/b59e1f291965f14fbee5172cd83a20f5b856204f/src/pke/include/encoding/ckkspackedencoding.h) 和 [实际解码实现](https://github.com/openfheorg/openfhe-development/blob/b59e1f291965f14fbee5172cd83a20f5b856204f/src/pke/lib/encoding/ckkspackedencoding.cpp)：默认 REAL 路径根据虚部估计误差，作共轭合并、加入高斯扰动，最终将返回值的虚部置零。因此 JSON 中的 `[real, imag]` 实际为 `[real, 0]`；它没有直接测量未投影的复槽范数。$E_1,E_2$ 包含输入/输出各次解码扰动之差及浮点误差，不能用来证明纯自举相位误差或突破解码观测精度的结论。原始 JSON 键名中的 `added_error` 和 `input_encoding_encryption_max_error` 也都应按这个实际测量定义解释。

校准和测量使用秘密钥解密作为**离线观测手段**；求值函数只依赖密文及公开求值钥。校准密文与测量密文分离。五位经验余量不能替代理论上的残差输入域条件，也不是对所有密钥和输入的最坏情形界。随机密钥和加密随机数采用库默认来源，固定输入使实验可复查，但结果并非逐位确定。

三组输入为：八个含正负号的二进制有理数；同样八个数统一增加 $\delta=2^{-10}$；八个含 $1/3,-2/7$ 等值的小数。第二组把 $m+\delta$ 加密，作为已经进入代表值的确定性扰动模型；它不声称按某一种加密噪声分布采样。

## 实际输出

以下九例的单轮观测差均小于 $10^{-4}$，两轮观测差均小于 $10^{-6}$ 且小于单轮观测差，两轮输出均有 10 个可用层级。一轮层级未单独记录。这些是本次实验的检查条件，不是对任意参数的算法保证。

| 独立密钥试验 | 输入组 | 一轮最大新增误差 | 两轮最大新增误差 | 一轮精度 / bit | 两轮精度 / bit |
|---|---|---:|---:|---:|---:|
| 1 | 1 | 8.510944e-08 | 1.665335e-13 | 23.486 | 42.449 |
| 1 | 2 | 3.652570e-08 | 1.095790e-13 | 24.707 | 43.053 |
| 1 | 3 | 5.203667e-08 | 9.681145e-14 | 24.196 | 43.232 |
| 2 | 1 | 3.654244e-08 | 8.354428e-14 | 24.706 | 43.444 |
| 2 | 2 | 4.187452e-08 | 8.509859e-14 | 24.509 | 43.418 |
| 2 | 3 | 2.501858e-08 | 1.368905e-13 | 25.252 | 42.732 |
| 3 | 1 | 2.836243e-08 | 5.673240e-14 | 25.071 | 44.003 |
| 3 | 2 | 5.827500e-08 | 6.672440e-14 | 24.033 | 43.769 |
| 3 | 3 | 6.980466e-08 | 4.207745e-14 | 23.772 | 44.434 |

一轮观测精度为 23.486–25.252 bit，两轮为 42.449–44.434 bit。九个样例中观察到的精度提高为 17.48–20.66 bit；实际收益受配置、校准余量、算术误差及解码观测影响，不能把“重复两次”直接写成无条件精确翻倍。输入解码观测值相对给定代表值的误差在 $2.00\times10^{-15}$ 至 $3.89\times10^{-15}$ 之间，已经单独记录；它也包含解码过程的误差。

### 已有误差没有被恢复

第二组输入的扰动为

$$
\delta=2^{-10}=0.0009765625.
$$

三次试验的两轮输出相对于未扰动目标 $m$ 的最大误差分别为：

| 试验 | 两轮输出相对原目标的最大误差 |
|---|---:|
| 1 | 0.0009765625001082467 |
| 2 | 0.0009765625000889289 |
| 3 | 0.0009765625000637268 |

因此，本次观察到的是两轮自举后输出相对于输入的**解码观测差**大幅下降；原先的 $2^{-10}$ 扰动仍然保留。其测量语义对应 $v_{in}=m+\delta+e_{in}$、$v_{out}=v_{in}+e_{new,obs}$，其中 $e_{in}$ 包括输入编码、加密及解码误差，$e_{new,obs}$ 包括输出/输入解码观测之差。没有给算法一个能识别原目标 $m$ 的额外信息。此现象与本轮确定性误差递推的预期一致，但观测量不应直接替换定理中的精确相位误差。

### API 的实际边界

该固定版本的这一接口只支持 1 或 2 轮；程序也确认传入 3 轮会被拒绝。论文中的一般 $k$ 轮构造与一个库接口已实现多少轮是两件不同的事。这里没有据接口限制否定论文的理论推广。

## 复现

需要 Git、支持 C++17 的编译器、CMake、Make 和 Python 3。库在本地构建并安装到实验目录，不要求写入系统目录。

```sh
git clone --depth 1 --branch v1.6.1 --recurse-submodules \
  https://github.com/openfheorg/openfhe-development.git ../openfhe-v1.6.1
python3 audit/run_openfhe_meta_bts.py \
  --openfhe-source ../openfhe-v1.6.1 \
  --output build/openfhe-review/results.json
```

脚本核对完整上游提交，并拒绝修改过的上游受版本控制文件。若使用现成 CMake，可通过 `--cmake` 指定其路径。默认运行 3 个独立试验；每次都会保留成功或失败的结构化输出，不删除失败样本。可用 `--openfhe-build` 复用已有构建目录。

这是一次真实同态执行的有限核验，不提供安全参数认证、误差尾界证明或全输入域穷举。理论条件仍以 [CKKS 补充核验](ckks-followup.md) 为准；本实验只为其中的尺度、精度改善和已有误差保留现象提供独立实现证据。
